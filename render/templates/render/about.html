About This Project

A small Django + Django REST Framework student management app.

Stack

  • Django 6.1 with SQLite
  • Django REST Framework for the JSON API
  • Django templates for the HTML pages

Pages

  • Home — live list, with edit and delete links per row
  • Add — POST a new student
  • Update — PUT every field at once
  • Partial Update — PATCH only the changed fields
  • Delete — DELETE a student

API endpoints

Method URL Purpose
GET {% url 'student-list' %} List all students
POST {% url 'student-list' %} Create a student
GET {% url 'student-list' %}1/ Retrieve one student
PUT {% url 'student-list' %}1/update/ Full update
PATCH {% url 'student-list' %}1/partial-update/ Partial update
DELETE {% url 'student-list' %}1/delete/ Delete a student

How the forms talk to the API

Each form reads Django's {% verbatim %}{% csrf_token %}{% endverbatim %} token and sends it in the X-CSRFToken header. Validation errors returned by the API are rendered directly under the matching field, and the shared request helpers live in base.html.

Right now the API is anonymous, so DRF's SessionAuthentication does not enforce CSRF and requests work either way. As soon as you add login, that header becomes mandatory — the forms already send it, so nothing will break.
